Impermanence on box

This is the complete operating guide for this machine’s NixOS impermanence setup. Read “First activation” before applying the configuration.

What this setup does

Normally, every file written to Linux stays on disk. Here, the live root filesystem (/) is a tmpfs: a filesystem held in memory. Each boot starts with a fresh root, so files not explicitly preserved disappear at reboot. This is called impermanence.

It keeps operating-system state tidy and reproducible. It is not a backup, a security boundary, or disk encryption. Important files still need an independent backup, and persistent data remains unencrypted unless full-disk encryption was separately configured.

Glossary

NixOS
A Linux distribution configured with Nix expressions instead of manual edits under /etc.
Flake
A version-pinned Nix project. flake.nix describes inputs and outputs; flake.lock records exact revisions for repeatable builds.
Home Manager
The user-level configuration system. Here it manages Abhishek’s applications and home-directory settings from home.nix.
Generation
An immutable NixOS system version. Every successful rebuild creates one, and systemd-boot can start an older one.
Persistence
A disk-backed path mounted into the otherwise fresh tmpfs root or home directory.

Disk layout and design

This computer has one ext4 root partition, one EFI boot partition, and swap; there is no separate persistence partition. Nothing is reformatted or deleted. The existing ext4 root partition is mounted at /persist early in boot, the live / is an 8 GiB maximum tmpfs, and /nix is bind-mounted from /persist/nix. The Nix store stays on disk and is neither copied to memory nor lost on reboot.

The original disk contents remain below /persist. Do not reformat it, delete it, or mount over it: it holds both the Nix store and all persistent state.

Where the configuration lives

Everything is in /home/abhi/.dotfiles, not /etc/nixos. That repository is persistent.

  • flake.nix: declares Nixpkgs, Home Manager, and impermanence.
  • flake.lock: pins exact dependency revisions. Commit it whenever inputs change.
  • configuration.nix: machine-wide settings and system persistence.
  • home.nix: user settings and home-directory persistence.
  • hardware-configuration.nix: mounts the existing ext4 device at /persist. Its usual generated-file warning is overridden intentionally. Do not casually regenerate or overwrite it.

Exactly what survives a reboot

System paths

  • /etc/machine-id, keeping the machine identity stable.
  • Saved Wi-Fi/VPN connections, NetworkManager state, Bluetooth pairings, account data, and colour profiles.
  • Docker, Waydroid, NixOS, and systemd state.
  • /var/log, so logs remain available for debugging.

Abhi’s home-directory paths

  • .config, .local/share, and .local/state, including GNOME and Home Manager settings.
  • .ssh, .gnupg, .mozilla, .docker, .steam, and .android.
  • Android, Desktop, Documents, Downloads, Pictures, Projects, and .dotfiles.

Everything else is temporary unless it lives below one of those directories. In particular, unlisted top-level directories such as .cache, .cargo, .rustup, .npm, and tool-session directories such as .vibe reset at reboot. This can cause downloads or caches to be recreated; add a path only when retaining it is useful.

Before first activation

Make an independent backup first. The listed paths are designed to survive, but backups protect against configuration mistakes, hardware failure, and accidental deletion. Copy important documents, projects, SSH keys, GnuPG keys, and this repository to an external disk or trusted remote destination. Verify the backup is readable.
  • Keep the computer on AC power and do not force-power-off during a rebuild.
  • Save work and close important applications before rebooting.
  • Ensure the current system boots normally before making the change.
  • sudo asks for the account password. Nothing appears while entering it; that is normal.

First activation

Run these commands in a terminal. The first builds and validates without changing the running system. The second activates a new generation. The reboot is when the tmpfs root takes effect.

cd /home/abhi/.dotfiles
sudo nixos-rebuild build --flake .#box
sudo nixos-rebuild switch --flake .#box
sudo reboot

Do not use nixos-rebuild against /etc/nixos on this machine. The .#box selects the box configuration in this repository. The initial reboot may take a little longer while mounts and services start.

Verify it worked

After logging in again, run:

findmnt / /persist /nix
touch /tmp/impermanence-test
sudo reboot

After the next login, confirm the temporary test is gone:

test ! -e /tmp/impermanence-test && echo "temporary file was removed"

Also check ~/Projects, ~/.ssh, Wi-Fi, GNOME settings, and this repository. findmnt should show tmpfs for /, ext4 for /persist, and a bind mount for /nix.

Everyday Nix workflow

Edit the Nix files in this repository and apply changes with:

cd /home/abhi/.dotfiles
sudo nixos-rebuild switch --flake .#box

No separate home-manager switch is needed; Home Manager is integrated. Use sudo nixos-rebuild test --flake .#box to activate only until the next reboot, or sudo nixos-rebuild build --flake .#box to build without activating.

To update only impermanence later, run nix flake update impermanence, review the flake.lock diff, then rebuild. Updating inputs is optional and not needed for ordinary edits.

Making another path persistent

If an application loses important state, first find where it writes files. User paths are commonly in ~/.config, ~/.local/share, or a dot-directory; system services often use /var/lib.

  1. For an Abhi home-directory path, add its relative name to directories in home.nix. Example: add ".vibe" to retain that tool’s state.
  2. For a system directory, add its absolute path to environment.persistence."/persist".directories in configuration.nix. Example: "/var/lib/example-service".
  3. For a single system file, add its absolute path to the files list instead.
  4. Run sudo nixos-rebuild switch --flake /home/abhi/.dotfiles#box, reboot, and test it.

Prefer the smallest required path. Do not add all of /home, /var, or /; that would largely defeat impermanence.

Recovery and troubleshooting

  • A path disappeared: look for its old copy under /persist/home/abhi (or /persist/var for system data), add the path to the appropriate list, rebuild, and reboot. Copy it back only after confirming the persistent mount is correct.
  • The new generation does not boot: at the systemd-boot menu select an older NixOS generation. It uses the earlier configuration, allowing you to fix the repository and rebuild.
  • Root tmpfs is full: 8 GiB is a maximum allocation, not memory reserved at boot. Clear temporary files or adjust size=8G in configuration.nix, then rebuild. The Nix store is disk-backed at /nix.
  • /persist or /nix did not mount: boot a previous generation and inspect the UUID in hardware-configuration.nix. Never format the ext4 volume; it contains recovery data.
  • Undo the last generation: after booting, sudo nixos-rebuild switch --rollback selects the preceding generation. It does not delete data.

Safety limits

  • Impermanence is not secure deletion, encryption, or a backup.
  • Do not run nixos-generate-config casually; it can overwrite the required /persist mount in hardware-configuration.nix.
  • Do not manually remove, reformat, or mount over /persist.
  • When adding a new application, test one reboot before relying on its data.
